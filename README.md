# Unigram-Watermark

A Python implementation of **Unigram-Watermark**, a watermark for text generated by large language models, from:

> Xuandong Zhao, Prabhanjan Ananth, Lei Li, Yu-Xiang Wang. *Provable Robust Watermarking for AI-Generated Text.* arXiv:2306.17439 (ICLR 2024).

## How it works

1. **Watermark (Algorithm 1):** a secret key randomly splits the model's vocabulary into a *green list* (a fraction γ of all tokens) and a *red list*. The split is fixed for the whole text. While generating, the logits of green tokens get a bonus δ, so the model picks green tokens a bit more often. The text still reads naturally.
2. **Detect (Algorithm 2):** whoever has the key counts the green tokens in a text and computes a z-score: `z = (|y|_G − γn) / sqrt(nγ(1−γ))`. Human text has about γ·n green tokens (z ≈ 0). Watermarked text has many more. If `z > τ` (τ = 6 in the paper), the text is flagged as watermarked.
3. **Detect "Unique" (Algorithm 4):** the same test, but each distinct token is counted once, with the threshold from Eq. (9). This keeps the false positive rate at a chosen level α, even for repetitive text.

Default parameters match the paper: γ = 0.5, δ = 2.0, nucleus sampling (top-p = 0.9).

## Project structure

```
unigram_watermark/
    core.py         # UnigramWatermark class: green list, Algorithms 1, 2 and 4
    generation.py   # text generation with a Hugging Face model, TPR@FPR, random edits
tests/
    test_core.py    # checks against Theorems 3.1 and 3.7 and the false positive rate

```

## Usage

Run the tests (fast, no model download):

```bash
pytest -q
```

Run the demo with a real model (a GPU is recommended; on CPU use fewer prompts):

```bash
python demo.py
python demo.py --num-prompts 5 --max-new-tokens 100           # quicker
python demo.py --model facebook/opt-1.3b --no-chat-template   # a model used in the paper
```

The demo prints detection results and saves `results/z_scores.png` and `results/example_colored.html` (green and red tokens colored as in Table 1 of the paper).

Use it in your own code:

```python
from unigram_watermark import UnigramWatermark, generate

wm = UnigramWatermark(key=42, vocab_size=model.get_output_embeddings().weight.shape[0])
tokens, text = generate(model, tokenizer, "Why is the sky blue?", wm=wm)
print(wm.detect(tokens))         # Algorithm 2
print(wm.detect_unique(tokens))  # Algorithm 4
```

## Notes

- The watermark is added to the logits **before** temperature and top-p, as a Hugging Face logits processor does in `generate()`, which the authors used.
- **Theorem 3.7 (robustness to edits):** its proof (Appendix C.2) uses the statistic `(|y|_G − γn)/√n`, i.e. the z-score *without* the `√(γ(1−γ))` factor of Eq. (2). For the Eq. (2) z-score, the bound has to be divided by `√(γ(1−γ))`. The tests check both forms.
- Not reproduced: paraphrasing attacks (ChatGPT, DIPPER, BART) and the comparison with Kirchenbauer et al. (2023), since they need extra models.

# SynthID-Text (Tournament sampling)

A Python implementation of the **SynthID-Text** watermark (Tournament sampling, Algorithm 1), from:

> Sumanth Dathathri et al. *Scalable watermarking for identifying large language model outputs.* Nature 634 (2024).

## How it works

1. **Seed:** the last H tokens and a secret key are hashed into a seed `r_t`. Each (seed, token, layer) gives a pseudorandom bit `g_l(x, r_t)`, the g-value.
2. **Tournament (Algorithm 1):** draw 2^m candidate tokens from the model's distribution, pair them up and in layer l keep the one with the larger `g_l` (tie -> random). After m layers one token is left. If the context was already used in this text, plain sampling is used instead.
3. **Detect:** without the watermark every g-value is a fair coin. Whoever has the key computes the z-score of the sum of g-values over all tokens and layers. Repeated contexts are counted once. If `z > 2.326` (false positive rate 1%), the text is flagged as watermarked.

Default parameters: H = 4, m = 8 (256 candidates), top-k = 100, temperature = 0.7.

## Project structure

```
synthid_watermark/
    core.py         # TournamentWatermark class: seed, g-values, Tournament sampling, z-score
    generation.py   # text generation with a Hugging Face model, with or without the watermark
tests/
    test_synthid.py # checks: determinism, mean g = 3/4 for a flat distribution, z ~ N(0, 1) without watermark
demo_synthid.py     # end-to-end experiment: detection, perplexity, speed, random edits
```

## Usage

```bash
pytest -q
python demo_synthid.py
python demo_synthid.py --num-prompts 5 --max-new-tokens 100   # quicker
```

```python
from synthid_watermark import TournamentWatermark, generate

wm = TournamentWatermark(key="secret")
tokens, text = generate(model, tokenizer, "Why is the sky blue?", wm=wm)
print(wm.detect(tokenizer(text, add_special_tokens=False).input_ids))
```

## Notes

- Detection runs on the decoded text, tokenized again, as in real use.
- Perplexity is scored by the same model that generated the text, so it is only a rough quality check (the paper uses a bigger model).
- Not reproduced: the Bayesian (learned) detector and speculative sampling integration from the paper; only the mean-score detector is used.

# KGW (soft red list)

A Python implementation of the **KGW** watermark (Algorithm 2, soft red list), from:

> John Kirchenbauer, Jonas Geiping, Yuxin Wen, Jonathan Katz, Ian Miers, Tom Goldstein. *A Watermark for Large Language Models.* ICML 2023, arXiv:2301.10226.

## How it works

1. **Green list from the previous token:** the previous token and a secret key are hashed into a seed. The seed splits the vocabulary into a *green list* (a fraction γ of all tokens) and a *red list*. Unlike Unigram-Watermark, the split changes at every position.
2. **Watermark:** the logits of green tokens get a bonus δ, then the next token is sampled as usual (temperature, top-p).
3. **Detect:** whoever has the key rebuilds the green list of every token from the token before it, counts the green tokens and computes `z = (|s|_G − γT) / sqrt(Tγ(1−γ))`. If `z > 4`, the text is flagged as watermarked.

Default parameters match the paper: γ = 0.25, δ = 2.0, threshold z = 4.

## Project structure

```
kgw_watermark/
    core.py         # KGWWatermark class: green list from the previous token, watermark, z-score
    generation.py   # text generation with a Hugging Face model, with or without the watermark
tests/
    test_kgw.py     # checks: green list size and determinism, z ~ N(0, 1) without watermark, detection
demo_kgw.py         # end-to-end experiment: detection, perplexity, random edits
```

## Usage

```bash
pytest -q
python demo_kgw.py
python demo_kgw.py --num-prompts 5 --max-new-tokens 100   # quicker
```

```python
from kgw_watermark import KGWWatermark, generate

wm = KGWWatermark(key=42, vocab_size=model.get_output_embeddings().weight.shape[0])
tokens, text = generate(model, tokenizer, "Why is the sky blue?", wm=wm)
print(wm.detect(tokens))
```

## Notes

- Only the soft red list (Algorithm 2) is implemented. The hard red list (Algorithm 1) and beam search are not.
- The first generated token uses the last prompt token as its previous token. The detector does not see the prompt, so it scores tokens 2..T.
- Perplexity is scored by the same model that generated the text, so it is only a rough quality check.
